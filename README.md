# Mesto

Учебное приложение для публикации фотографий. Проект выполнен на основе
[заготовки Яндекс Практикума](https://github.com/Yandex-Practicum/mesto-ad).

## Возможности

- Загрузка профиля и карточек с сервера группы.
- Редактирование имени, занятия и аватара.
- Добавление карточек и удаление собственных карточек.
- Постановка и снятие лайков, отображение их количества.
- Просмотр фотографии в отдельном модальном окне.
- Валидация всех форм с сообщениями об ошибках.
- Состояния «Сохранение...» и «Создание...» во время отправки данных.
- Вариант 1: информация о карточке по кнопке «i», включая актуальные лайки.

## Технологии

HTML, CSS, JavaScript (ES Modules), Fetch API, Promise, Vite, GitHub Pages.

## Запуск

Требуется Node.js 22.12 или новее.

```bash
npm ci
npm run dev
```

Сервер разработки открывает адрес `http://127.0.0.1:5173/`.
В настройках явно указан IPv4-адрес, чтобы запуск не зависел от разрешения имени `localhost`.
Если порт занят, используйте адрес с портом, который напечатан в терминале.

Перед первым запуском скопируйте `.env.example` в `.env.local` и заполните:

```dotenv
VITE_MESTO_TOKEN=личный_токен
VITE_MESTO_COHORT=идентификатор_группы
```

Токен и группу выдают через форму в уроке «Mesto. Работа с сервером».
Файл `.env.local` исключён из Git. После изменения этого файла перезапустите сервер.
Учебный API-токен используется в браузере и входит в собранный JavaScript;
переменные Vite не являются способом скрыть клиентские данные от посетителей сайта.

В локальной копии для Windows можно запустить `START.cmd` двойным щелчком.
Если используется переносимая Node.js из папки `.runtime`, команды из терминала
выполняются через `./npm-local.cmd`, например `./npm-local.cmd run dev`.
Папки `.runtime` и `node_modules` в репозиторий не отправляются.

## Сборка

```bash
npm run build
npm run preview
```

Готовые файлы находятся в `dist`. Параметр `base: './'` в `vite.config.js`
задаёт относительные пути к ресурсам для GitHub Pages.
Открывать исходный `index.html` двойным щелчком вместо сервера не нужно.

## Структура JavaScript

| Файл | Назначение |
| --- | --- |
| `src/scripts/index.js` | Инициализация, обработчики событий и форм, отображение ответов сервера |
| `src/scripts/components/api.js` | Запросы к API и проверка `response.ok` |
| `src/scripts/components/card.js` | Создание, удаление и обновление разметки карточек |
| `src/scripts/components/modal.js` | Открытие и закрытие модальных окон |
| `src/scripts/components/validation.js` | Универсальная валидация с объектом настроек |

## Публикация на GitHub Pages

По условиям курса исходный код хранится в **приватном** репозитории.
Для сборки создаётся отдельный **публичный** репозиторий, например `mesto-pages`.
В нём размещается только содержимое `dist`.

### Автоматически через GitHub Actions

В приватном репозитории добавьте секреты:

- `PUBLIC_PAGES_TOKEN` — GitHub PAT с правами для публикации в выбранный репозиторий;
- `PUBLIC_PAGES_REPO` — `владелец/mesto-pages`;
- `VITE_MESTO_TOKEN` — учебный токен Mesto;
- `VITE_MESTO_COHORT` — идентификатор группы;
- `PUBLIC_PAGES_BRANCH` — необязательно, по умолчанию `main`.

Workflow `.github/workflows/deploy.yml` собирает проект после push в `main`
или ручного запуска и отправляет `dist` в публичный репозиторий.
В его настройках Pages выберите публикацию из ветки `main`, папка `/ (root)`.

### Из терминала

Добавьте в `.env.local` строку `PUBLIC_PAGES_REPO=владелец/mesto-pages`.
Убедитесь, что Git авторизован в вашем аккаунте, затем выполните:

Для публикации из терминала также должны быть настроены `git config user.name`
и `git config user.email` — имя и почта автора коммитов.

```bash
npm run deploy
```

Команда сначала выполняет сборку, затем публикует только её содержимое в отдельный
публичный репозиторий. Репозиторий нужно создать заранее.

### Ссылка на проект

Публикация выполняется владельцем репозитория. После неё добавьте сюда фактическую
ссылку из Settings → Pages. Адрес имеет вид `https://владелец.github.io/mesto-pages/`.
